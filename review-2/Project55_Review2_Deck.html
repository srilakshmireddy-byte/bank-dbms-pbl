Normalization Process — UNF to 3NF

UNF

One bank sheet: customer, branch, account, joint holders, many transactions and loan instalments repeated in a single record.

›

1NF

Atomic values; repeating groups (holders, transactions, instalments) moved to their own rows. Primary key added.

›

2NF

Partial dependencies removed. Branch and type data split from ACCOUNT; ACCOUNT_HOLDER resolves the M:N of joint accounts.

›

3NF

No transitive dependencies. Subtypes (TRANSFER, SERVICE_CHARGE, LOAN_REPAYMENT) hang off TRANSACTION; REPAYMENT allocates payments to schedule rows.

Example of a removed anomaly

  • Before: account row stored branch name, city and manager — changing a manager meant editing every account.
  • After: ACCOUNT stores only branch_id; BRANCH holds the details once.

Result

  • No update, insert or delete anomalies.
  • Every non-key attribute depends on the key, the whole key, and nothing but the key.

05 / 16

Changes from Review 1 Schema to 3NF

Design decisions

  • TRANSFER stores two references — debit and credit transaction — so every transfer is balanced by construction; amount is read from the ledger, not duplicated.
  • REPAYMENT allocates a payment transaction to a LOAN_SCHEDULE instalment, so outstanding = scheduled − allocated.
  • Customer / branch / type details kept in a single place and referenced by key.
  • ACCOUNT_HOLDER resolves the many-to-many between customers and joint accounts.

Controlled redundancy

  • account.balance and transaction.balance_after are computed by the BEFORE/AFTER INSERT triggers — never typed by users.
  • Audit query confirms zero mismatches between the stored balance and the last ledger entry.
  • Money columns use DECIMAL(15,2), never floating point.

All 14 entities from the Review 1 ER diagram are retained — the ER diagram is unchanged.

Transaction Posting Flow — Enforced in the Database

1. Request

INSERT into TRANSACTION, or CALL sp_transfer / sp_loan_repayment.

›

2. Validate

BEFORE INSERT trigger checks: amount > 0, account exists, status ACTIVE.

›

3. Balance check

Credit: new = balance + amount. Debit: new = balance − amount must be ≥ minimum balance.

›

4. Post

balance_after stored; AFTER trigger updates ACCOUNT.balance.

Transfer = one atomic unit

  • Debit leg on the source account and credit leg on the destination are inserted inside one transaction.
  • If either leg fails, ROLLBACK undoes both — money is never created or lost.

Loan repayment

  • EMI is debited from the loan account and linked to the matching schedule row.
  • When the instalment is fully paid its status becomes PAID automatically.
